# План развития Albus Audio

## Порядок работ
1. **Сохранение настроек** — конфиг на диске (час-два, чинит сброс при каждом запуске)
2. **Стабильная личность и друзья** — без стабильного ID друзья не работают
3. **Трансляция экрана 1440p60** — самый крупный этап
4. **Звук: несколько входов и профили источника** — микрофон с одной карты, гитара со второй
5. Опционально: 4K, кроссплатформенность (раздел ниже)

## 1. Сохранение настроек
- [x] Модуль `config.rs`: `%APPDATA%\Albus\config.ini` — свой формат `ключ=значение`, без новых зависимостей
- [x] Устройства ввода/вывода хранить по **имени**, а не по индексу (индексы плывут при подключении новых устройств); при старте имя → устройство через `DeviceSelector`, fallback — устройство по умолчанию
- [x] Сохранять: PTT VK, громкости ch1/ch2/выхода, каналы входов, `continuous_mode`; громкость по собеседникам — на этапе друзей (нужен стабильный NodeID)
- [x] Запись на изменение в UI с троттлингом 400 мс, а не в `on_exit` (не сработает при краше)
- [x] eframe storage не используем: отдельный файл переносимее

## 2. Личность и друзья (без своего сервера)
- [x] Стабильный NodeID: закрепить `SecretKey` iroh (проверить, не делает ли это уже `presets::N0`); ключ остаётся в ведении iroh, криптография не меняется
- [x] `my_id: u64` — короткий псевдоним (хеш NodeID), стабилен между запусками; `rand::random()` убрать (это метка UI, не ключ)
- [x] Привязка `sender_id ↔ NodeID` в handshake: сейчас `sender_id` из пакета не проверяется, можно выдать себя за другого
- [x] `%APPDATA%\Albus\friends.json`: node_id, имя, дата; список друзей в UI с кнопкой «Позвонить» (dial по NodeID, discovery N0)
- [x] Новые `NetworkMessage`: `FriendRequest`, `FriendAccept`, `FriendRemove`; не доставленные заявки — pending, переотправка при следующем соединении
- [ ] Онлайн-статус: ping/connect по NodeID, офлайн = таймаут (механизм dial есть; индикатора онлайн/офлайн в списке друзей пока нет)

### Звонки как в Discord
Сейчас «Позвонить» сразу подключает к другу и тот оказывается в комнате — согласия нет.
- [ ] `CallInvite` / `CallAccept` / `CallDecline` (новые теги в `message.rs`) с `call_id`:
  в комнату собеседник попадает только после «Принять»
- [ ] Оверлей «Звонок от …» с «Принять» / «Отклонить»; у звонящего — «Звоним…» с отменой
- [ ] Таймаут ~30–45 с → «Не ответил»; звонок во время звонка → «Занято»
- [ ] Отклонение и отмена видны обеим сторонам, а не молчаливым таймаутом
- [ ] Онлайн-статус (пункт выше) нужен и здесь: «Позвонить» по офлайн-другу сразу говорит, что он не в сети
- [ ] Звук входящего звонка и повтор уведомления, пока не ответили
- [x] «Сбросить личность» в настройках: стабильный ID позволяет узнавать пользователя между запусками

## 3. Трансляция экрана (1080p / 1440p60)

### Сделано
- [x] Захват нативно, без ffmpeg: DXGI Desktop Duplication, кадр остаётся на GPU
- [x] Конверсия BGRA→NV12 на GPU через `ID3D11VideoProcessor` (там же масштаб под пресет)
- [x] Аппаратный H.264 через Media Foundation MFT (NVENC/AMF/QSV), CBR и GOP через `ICodecAPI`
- [x] Отдельное iroh-соединение `ALPN "discordrf-video/1"`, один uni-стрим на кадр; голос остаётся датаграммами
- [x] Пресеты от числа пикселей: 1080p60 ≈ 8.7 Мбит/с, 1440p60 ≈ 18 Мбит/с; захват в нативном разрешении, без апскейла
- [x] Показ: MF-декодер → NV12 → BGRA на GPU → `egui::TextureHandle`; отдельное растягиваемое окно + полноэкранный режим
- [x] Локальное превью своей трансляции (клик по превью открывает окно)
- [x] Headless-проверки без GUI: `tools/video_probe --capture / --gpu / --loopback`
- [x] Стабильность приёма: очередь зрителя ограничена 30 кадрами с ресинком по ключевому кадру, показ не чаще частоты потока, проверка длины NV12 перед загрузкой в D3D, fps в UI считается за секунду, а не суммой кадров
- [x] Частота трансляции 30/60 fps на выбор (`video_fps` в config.ini, по умолчанию 60); в строке трансляции видны fps показа и fps кодирования — так видно, упирается ли пайплайн в захват/энкодер или в показ
- [x] Неблокирующее чтение кадра с GPU и превью в половинном разрешении; в UI видны миллисекунды по этапам (декод / чтение с GPU / картинка)
- [x] Показ идёт на полной частоте потока: порог 75% периода (на 75 Гц мониторе) и отложенный кадр вместо выброшенного — 60 fps
- [x] Окно зрителя показывает миллисекунды показа (декод / чтение с GPU / картинка) рядом с FPS — по ним видно, упирается приём в его компьютер или в сеть
- [x] Повторные старт/стоп не текут: `VideoLink::stop_viewers()` закрывает видео-соединения со зрителями (без дублей по NodeID), недосмотренные кадры умершего потока выбрасываются
- [x] Утечки в кадровом пути закрыты: выходной сэмпл MFT и входной вид видеопроцессора больше не забываются (`ManuallyDrop` без `Drop` у обёрток); проверка без GUI — `tools/video_probe/src/bin/cycles.rs` крутит старт/стоп и печатает память по кругам
- [x] Штамп сборки в консоли (`[СБОРКА] Albus … · сборка …`): у собеседников он должен совпадать — видно, если у кого-то запущен старый exe

### Осталось
- [ ] Топология publisher → хост → зрители: хост форвардит сжатые байты без ре-энкода, его upload = N × битрейт
- [ ] Подписка зрителей, вошедших после старта трансляции; выбор адресатов вместо «всем в комнате»
- [ ] Буфер воспроизведения ~2 с (настраиваемый): сдвиг deadline, досыл потерянных пакетов, ровный битрейт и длинный GOP
- [ ] Адаптивное снижение битрейта по обратной связи; видео только прямым путём — fallback на релей означает понижение качества
- [ ] Ограничение полосы и приоритет голоса над видео (сейчас голос защищён только отдельным QUIC-соединением)
- [ ] HEVC/AV1, когда их аппаратный декод будет у всех зрителей; 4K60 по разрешению пайплайн не ограничивает — проверить на живом энкодере
- [ ] Захват окна (Windows Graphics Capture) и камера — новый источник кадров подключается к тому же энкодеру

## 4. Звук: несколько входов и профили источника

### Сделано
- [x] DSP передачи: noise gate (−44 dBFS) → `TransmitAgc` (цель −20 dBFS RMS) →
  `Limiter` (−1 dBFS) → Opus 64 кбит/с моно; без AGC тихий микрофон уходил в
  эфир тихим, и громкость добиралась уже у собеседника
- [x] Приём: свой Opus-декодер, буфер и порядок пакетов на каждого собеседника;
  потери не блокируют воспроизведение (пропуск при трёх накопленных), маскируются
  повтором с затуханием, предбуфер 60 мс; счётчики провалов/потерь в консоли
- [x] Микс: громкость участника в дБ (−30…+18) поверх общей громкости, один
  лимитер на готовый микс, общий мьют
- [x] Прослушивание своего тракта в настройках: слышно то, что услышит собеседник,
  независимо от PTT
- [x] Формат вывода по возможностям карты: f32 → i32 → i16; многоканальные выходы
  (7.1) больше не размазывают голос по всем каналам, виртуальный 7.1 Razer не
  свистит в `f32` — на нём открывается i32
- [x] Горячая смена микрофона и динамиков без перезапуска приложения
  (`gui/stream_control.rs`)

### Осталось
Сейчас приложение берёт **одно** стерео-устройство ввода и открывает **один**
выход. Блоки «МИКРОФОН»/«ГИТАРА» — это роли, а не физические каналы: внутри
каждого выбирается канал устройства. Из-за этого гитара и микрофон обязаны быть
на одной карте, а отдельные эффекты на источник включить некуда.

- [ ] Несколько входных устройств одновременно: отдельный cpal-стрим на каждое
  устройство (микрофон с одной карты, гитара со второй, при необходимости —
  USB-микрофон плюс вход встроенной), у каждого свой канал, громкость и VU-метр
- [ ] Эффекты на источник с выключателями: гейт вкл/выкл, AGC вкл/выкл, лимитер
  всегда последним (он защищает Opus)
- [ ] Профили входа «Голос» / «Инструмент»: голос — гейт + AGC + лимитер;
  инструмент — без AGC (он осаживает удары и «дышит» на затухающих нотах),
  гейт выключен или порог ниже, лимитер остаётся
- [ ] Подписи «Вход 1 / Вход 2» с выбором роли вместо жёстких «МИКРОФОН»/«ГИТАРА»
- [ ] Opus под музыку: сейчас 64 кбит/с моно на общий поток (`audio.rs`) — для
  гитары это потолок качества (предэхо, «варбл» на стереоэффектах); параметр
  64/96/128 или повышение, когда в миксе есть инструмент
- [ ] Шумоподавление (RNNoise или спектральное): гейт режет только тишину —
  клавиатура, кулер и вентилятор выше −44 dBFS проходят в эфир
- [ ] Эхо-подавление (AEC) для тех, кто в колонках: сейчас свой голос возвращается
  собеседнику эхом, лечится только наушниками

## Кроссплатформенность

### Linux
- [ ] `firewall.rs` целиком на `netsh` — обернуть в `#[cfg(windows)]` и добавить заглушку
- [ ] `keybind.rs` использует Win32 `GetAsyncKeyState` — нужен глобальный хоткей через X11/Wayland
- [ ] `audio.rs`/cpal на ALSA или PulseAudio — проверить выбор устройств и частоты
- [ ] iroh STUN/hole punching и релеи — проверить, что работают без прав администратора

### macOS
- [ ] Собирать `.app`-бандл, а не голый бинарник: без него окно не ведёт себя как приложение
- [ ] Универсальная сборка `x86_64-apple-darwin` + `aarch64-apple-darwin` (GitHub-раннеры уже arm64)
- [ ] Ad-hoc подпись и снятие карантина при распространении, иначе Gatekeeper убивает процесс
- [ ] `keybind.rs` — глобальный перехват через `CGEventTap` вместо Win32
- [ ] cpal на macOS работает через CoreAudio, отдельной работы не требует

### Android
- [ ] cpal не поддерживает Android — нужен Oboe (крейт `oboe`) и JNI-мост к Rust-ядру
- [ ] eframe/winit на Android — отдельная Activity через `android-activity`
- [ ] `keybind.rs` — кнопки громкости как PTT вместо глобального хука
- [ ] Интерфейс: портретная ориентация, крупные зоны нажатия, список участников в приоритете

## Ограничение среды разработки
VM, на которой идёт разработка (Hyper-V), отдаёт только OpenGL 1.1, а `egui_glow`
требует 2.0+. GUI там не запускается вообще — интерфейс проверяется на машине
пользователя по скриншотам. Если когда-нибудь понадобится гонять приложение в VM,
понадобится перевод eframe на бэкенд `wgpu` (DX12/WARP) либо программный OpenGL.
