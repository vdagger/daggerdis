# План развития Albus Audio

## Порядок работ
1. **Сохранение настроек** — конфиг на диске (час-два, чинит сброс при каждом запуске)
2. **Стабильная личность и друзья** — без стабильного ID друзья не работают
3. **Трансляция экрана 1440p60** — самый крупный этап
4. **Звук: несколько входов и профили источника** — микрофон с одной карты, гитара со второй
5. Опционально: 4K, кроссплатформенность (раздел ниже)

## 1. Сохранение настроек
- [x] Модуль `config.rs`: `%APPDATA%\Albus\config.ini` — свой формат `ключ=значение`, без новых зависимостей
- [x] Устройства ввода/вывода хранить по **имени**, а не по индексу (индексы плывут при подключении новых устройств); при старте имя → устройство через `DeviceSelector`, fallback — устройство по умолчанию
- [x] Сохранять: PTT VK, громкости ch1/ch2/выхода, каналы входов, `continuous_mode`; громкость по собеседникам — на этапе друзей (нужен стабильный NodeID)
- [x] Запись на изменение в UI с троттлингом 400 мс, а не в `on_exit` (не сработает при краше)
- [x] eframe storage не используем: отдельный файл переносимее

## 2. Личность и друзья (без своего сервера)
- [x] Стабильный NodeID: закрепить `SecretKey` iroh (проверить, не делает ли это уже `presets::N0`); ключ остаётся в ведении iroh, криптография не меняется
- [x] `my_id: u64` — короткий псевдоним (хеш NodeID), стабилен между запусками; `rand::random()` убрать (это метка UI, не ключ)
- [x] Привязка `sender_id ↔ NodeID` в handshake: сейчас `sender_id` из пакета не проверяется, можно выдать себя за другого
- [x] `%APPDATA%\Albus\friends.json`: node_id, имя, дата; список друзей в UI с кнопкой «Позвонить» (dial по NodeID, discovery N0)
- [x] Новые `NetworkMessage`: `FriendRequest`, `FriendAccept`, `FriendRemove`; не доставленные заявки — pending, переотправка при следующем соединении
- [x] Онлайн-статус: `PresencePing`/`PresencePong` (теги 15/16) раз в 4 с, TTL 12 с; зелёная/серая точка в списке друзей, «Позвонить» офлайн-другу сразу показывает тост «не в сети» вместо 35 с гудка

### Голосовая комната на N (как в Discord)
Сделано: комната — это и есть разговор; приглашение зовёт в неё, второй и третий
друг приглашаются в ту же комнату, а не получают «вы уже в звонке».
- [x] `CallInvite` / `CallAccept` / `CallDecline` + `CallCancel` / `CallEnd` (теги 10–14 в `message.rs`) с `call_id`:
  в комнату собеседник попадает только после «Принять»; приглашение переотправляется раз в 1.5 с
- [x] Оверлей «Входящий звонок» с «Принять» / «Отклонить»; у звонящего — «Звоним…» с отменой; в разговоре — крупная красная «Завершить звонок» и таймер; `Esc` завершает/отменяет/отклоняет
- [x] Входящий звонок подсвечивает приложение в панели задач (`RequestUserAttention`), если окно свёрнуто
- [x] Надёжная доставка приглашений: `send_bytes` выбрасывает мёртвое соединение, переподключается и повторяет, а при неудаче датаграм шлёт uni-стримом — раньше приглашение уходило «в пустоту», и у звонящего шёл гудок без отклика
- [x] «Выйти из эфира»: завершает звонок, чистит участников, рвёт соединения и не даёт IrohSync вернуть их обратно
- [x] Отказ/завершение держат собеседника вне комнаты час (было 45 с — завершённый звонок «возобновлялся»); снимается новым звонком или «Войти»
- [x] Таймаут: исходящий 35 с, входящий 45 с → «Не ответил» / «Пропущенный звонок»; звонок во время звонка → «Занято»
- [x] Отклонение и отмена видны обеим сторонам тостом, а не молчаливым таймаутом
- [x] Карточка «Принять / Отклонить» исчезает сразу после ответа, а разговор
  показывается компактной пилюлей в углу (LIVE, ник, таймер, «Завершить») —
  раньше оверлей висел поверх трансляции весь звонок, а устаревшая `Incoming`
  могла затирать только что установленную `Active`
- [x] `call_id` сверяется во всех ответах: запоздавший `Accept`/`Decline`/`End`
  от предыдущего звонка больше не поднимает и не рвёт текущий
- [x] Звук входящего и исходящего звонка синтезируется в аудио-колбэке, без файлов; повторяется, пока не ответили
- [x] «Позвонить» по офлайн-другу сразу говорит, что он не в сети (онлайн-статус из пункта выше)
- [x] «Сбросить личность» в настройках: стабильный ID позволяет узнавать пользователя между запусками
- [x] Групповой созвон: 
oom_id вместо пары «звонящий/принявший», pending —
  несколько приглашений одновременно (переотправка, таймауты), отказ блокирует
  только отказавшегося, «Завершить» выходит из комнаты, остальные остаются
- [x] RoomMembers (тег 17): пригласивший в ответ на CallAccept отдаёт список
  комнаты, новый участник соединяется с каждым — без этого группа из трёх не
  слышит друг друга (он знал только пригласившего)
- [x] In-band FEC и PLC на приёме: потерянный кадр восстанавливается копией из
  следующего пакета, затем продолжением сигнала по модели, а не повтором
  последнего кадра (повтор и звучал «роботом»); FEC виден счётчиком в диагностике
- [ ] Адаптивный packet_loss_perc по реальным потерям QUIC (сейчас 8 %
  фиксировано) и джиттер голоса в отчёте

## 3. Трансляция экрана (1080p / 1440p60)

### Сделано
- [x] Захват нативно, без ffmpeg: DXGI Desktop Duplication, кадр остаётся на GPU
- [x] Конверсия BGRA→NV12 на GPU через `ID3D11VideoProcessor` (там же масштаб под пресет)
- [x] Аппаратный H.264 через Media Foundation MFT (NVENC/AMF/QSV), CBR и GOP через `ICodecAPI`
- [x] Отдельное iroh-соединение `ALPN "discordrf-video/1"`, один uni-стрим на кадр; голос остаётся датаграммами
- [x] Пресеты от числа пикселей: 1080p60 ≈ 8.7 Мбит/с, 1440p60 ≈ 18 Мбит/с; захват в нативном разрешении, без апскейла
- [x] Показ: MF-декодер → NV12 → BGRA на GPU → `egui::TextureHandle`; отдельное растягиваемое окно + полноэкранный режим
- [x] Локальное превью своей трансляции (клик по превью открывает окно)
- [x] Headless-проверки без GUI: `tools/video_probe --capture / --gpu / --loopback`
- [x] Стабильность приёма: очередь зрителя ограничена по числу кадров (от буфера, 96..600) с ресинком по ключевому кадру, показ не чаще частоты потока, проверка длины NV12 перед загрузкой в D3D, fps в UI считается за секунду, а не суммой кадров
- [x] Частота трансляции 30/60 fps на выбор (`video_fps` в config.ini, по умолчанию 60); в строке трансляции видны fps показа и fps кодирования — так видно, упирается ли пайплайн в захват/энкодер или в показ
- [x] Неблокирующее чтение кадра с GPU и превью в половинном разрешении; в UI видны миллисекунды по этапам (декод / чтение с GPU / картинка)
- [x] Показ идёт на полной частоте потока: порог 75% периода (на 75 Гц мониторе) и отложенный кадр вместо выброшенного — 60 fps
- [x] Окно зрителя показывает миллисекунды показа (декод / чтение с GPU / картинка) рядом с FPS — по ним видно, упирается приём в его компьютер или в сеть
- [x] Повторные старт/стоп не текут: `VideoLink::stop_viewers()` закрывает видео-соединения со зрителями (без дублей по NodeID), недосмотренные кадры умершего потока выбрасываются
- [x] Утечки в кадровом пути закрыты: выходной сэмпл MFT и входной вид видеопроцессора больше не забываются (`ManuallyDrop` без `Drop` у обёрток); проверка без GUI — `tools/video_probe/src/bin/cycles.rs` крутит старт/стоп и печатает память по кругам
- [x] Штамп сборки в консоли (`[СБОРКА] Albus … · сборка …`): у собеседников он должен совпадать — видно, если у кого-то запущен старый exe
- [x] Подписка зрителей: номер трансляции анонсируется в `IrohSync` (`video_gen`), зритель сам подключается к живому потоку — вошедший в комнату после старта видит её в пределах секунды; издатель шлёт только подписчикам
- [x] Поздний зритель начинает с ближайшего ключевого кадра: издатель всегда держит окно недавних кадров (180 / 64 МиБ), подписка отдаёт хвост без дыр под одним замком с `publish`
- [x] Буфер показа у зрителя ~2 с (`video_buffer_ms`, 0..5000, слайдер в «ЭКРАН»): кадр показывается по дедлайну прихода, отставший придерживает следующие; в тулбаре окна зрителя видно текущий буфер
- [x] Топология publisher → хост → зрители: издатель отдаёт хосту один feed (kind=4), хост раздаёт те же сжатые байты зрителям (kind=5) и себе в окно, без ре-энкода; upload издателя = 1 × битрейт, хоста = N × битрейт. Маршрут выбирается по состоянию комнаты (`choose_view_route`/`choose_feed_target`), вещающий хост релеем не бывает, фолбэка на другую топологию нет — сборки обязаны совпадать по штампу

### Осталось
- [x] Досыл потерянных кадров (NACK): номер кадра на проводе, `kind 6`, досыл из кольца отдающей стороны, вставка по номеру у зрителя
- [ ] Ровный битрейт и длинный GOP под буфер
- [x] Адаптивный битрейт: издатель следит за потерями канала feed (раз в секунду, QUIC-статистика) и опускает/поднимает целевой битрейт энкодера на ходу — вниз на 15 % при потерях > 0.5 %, вверх на 10 % потолка после 5 чистых секунд, не ниже четверти пресета
- [ ] Ограничение полосы и приоритет голоса над видео (сейчас голос защищён только отдельным QUIC-соединением)
- [ ] HEVC/AV1, когда их аппаратный декод будет у всех зрителей; 4K60 по разрешению пайплайн не ограничивает — проверить на живом энкодере
- [x] Захват окна: выбор источника в карточке трансляции («Весь экран» или окно). Через Windows Graphics Capture окно снимается независимо от перекрытия (`video/win_wgc.rs`); если система WGC не даёт — вырезка прямоугольника окна из кадра экрана (`video/win_windows.rs`, `Converter::set_source_rect`)
- [ ] Камера как источник кадров (Media Foundation Source Reader) — тот же энкодер

## 4. Звук: несколько входов и профили источника

### Сделано
- [x] DSP передачи (опционально, по умолчанию **выключен**): noise gate
  (−44 dBFS) → `TransmitAgc` (цель −20 dBFS RMS) → `Limiter` (−1 dBFS) → Opus
  64 кбит/с моно. Тумблер в настройках звука, `mic_processing=1` в config.ini:
  у одного из собеседников тракт «проглатывал» тихую речь, и его было плохо
  слышно — сырой микрофон честнее, обработку включают по желанию. Ресэмплер
  работает всегда
- [x] Микрофон открывается в формате карты (f32 → i16 → i32 → её умолчание):
  раньше поток всегда строился из `f32`, и на микрофоне, принимающем только
  `i16`, звука не было вовсе — собеседник слышал тишину при исправном приёме
- [x] Пропавшее из настроек устройство (USB-микрофон выдернули) заменяется
  системным по умолчанию, а не оставляет тракт без звука
- [x] Приём: свой Opus-декодер, буфер и порядок пакетов на каждого собеседника;
  потери не блокируют воспроизведение (пропуск при трёх накопленных), маскируются
  повтором с затуханием, предбуфер 60 мс; счётчики провалов/потерь в консоли
- [x] Микс: громкость участника в дБ (−30…+18) поверх общей громкости, общий
  мьют; лимитер готового микса теперь опционален (`rx_limiter=1`, по умолчанию
  выключен — громкость приёма ровно такая, какую выставили)
- [x] Прослушивание своего тракта в настройках: слышно то, что услышит собеседник,
  независимо от PTT
- [x] Формат вывода по возможностям карты: f32 → i32 → i16; многоканальные выходы
  (7.1) больше не размазывают голос по всем каналам, виртуальный 7.1 Razer не
  свистит в `f32` — на нём открывается i32
- [x] Горячая смена микрофона и динамиков без перезапуска приложения
  (`gui/stream_control.rs`)
- [x] Несколько входных устройств одновременно: отдельный cpal-поток на каждое
  (микрофон с одной карты, гитара со второй), у каждого свой канал, громкость и
  VU-метр. «То же устройство» возвращает прежнюю схему — две дорожки одной карты.
  Кадры для Opus собирает один поток (`txbus`), а не аудиоколбэки: у двух карт
  свои часы, и общий энкодер в колбэке давал бы рассинхрон и залипания
- [x] Профили входа «Голос» / «Инструмент»: голос — гейт + AGC, инструмент — без
  них (AGC осаживал удары и «дышал» на затухающих нотах); лимитер общий и, как
  раньше, работает только при включённой обработке
- [x] Подписи «Вход 1 / Вход 2» с выбором устройства и профиля вместо жёстких
  «МИКРОФОН»/«ГИТАРА»

### Осталось
- [x] Эффекты на источник с выключателями: у каждого входа свои «Шумодав»,
  «Затвор» и «AGC» (все по умолчанию выкл.), «Лимитер передачи» — отдельный
  тумблер последним в тракте. Профили «Голос»/«Инструмент» стали пресетами на
  все три тумблера, ручная правка даёт профиль «Свой»; старый `mic_processing`
  читается как прежнее «эффекты по профилю + лимитер»
- [x] Opus под музыку: битрейт передачи выбирается — 64 / 96 / 128 кбит/с
  (настройки звука → «Качество передачи», `opus_bitrate` в config.ini). На 64
  гитара получала предэхо на ударах и «варбл» на затухающих нотах. Переключение
  действует на ходу, протокол не меняется; выше 128 кбит/с моно смысла не имеет
- [x] Шумоподавление: RNNoise (`nnnoiseless`, чистый Rust) отдельным тумблером
  «Шумодав» у каждого входа (`input1_denoise`/`input2_denoise`). Гейт режет
  только тишину — клавиатура, кулер и вентилятор выше −44 dBFS проходили в
  эфир; шумодав гасит ровный шум и под речью. Профиль «Голос» включает его
  вместе с затвором и AGC, у «Инструмента» все три выключены
- [x] Эхо-подавление: AEC3 (`aec3_rs`, чистый Rust) отдельным тумблером «Эхо»
  у каждого входа (`input1_aec`/`input2_aec`, по умолчанию выключен, в профили
  не входит). Колонки играют голос собеседника, микрофон его слышит и
  возвращает — человек слышит себя эхом. AEC3 вычитает из микрофона опору из
  колбэка вывода (микс собеседников после общей громкости, без монитора и
  гудка), адаптируясь к акустике комнаты и задержке. Кадр 480 сэмплов (10 мс),
  карта не на 48 кГц — опора ресэмплится на месте. Для наушников тумблер
  не нужен и остаётся выключенным

## Ограничение среды разработки
VM, на которой идёт разработка (Hyper-V), отдаёт только OpenGL 1.1, а `egui_glow`
требует 2.0+. GUI там не запускается вообще — интерфейс проверяется на машине
пользователя по скриншотам. Если когда-нибудь понадобится гонять приложение в VM,
понадобится перевод eframe на бэкенд `wgpu` (DX12/WARP) либо программный OpenGL.
