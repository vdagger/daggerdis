## Что это за проект

P2P голосовая рация и клиент для созвонов: чистый Rust, транспорт iroh/QUIC
(датаграммы для голоса, отдельное соединение для видео), GUI на eframe/egui.
Без серверов: комнату держит один из участников, при его выходе — миграция хоста.
Уже работает: голос (2 входа, эффекты, PTT), звонки, друзья, онлайн-статус, DM-чат,
трансляция экрана 1080p/1440p 30/60 fps звездой publisher → host → viewers.

- Объём: ~15 400 строк в `src/` (46 файлов), крупнейшие — `gui/mod.rs` (2 317),
  `network/video_link.rs` (2 043), `calls.rs` (898).
- Тесты: 95 юнит-тестов (config, calls, txbus, mixer, message, video_link,
  video_directory, presence, room, audio) — все зелёные на 2026-11-21.
- Платформы: Windows — основной таргет (видео только Windows);
  Linux/macOS собираются частично, готовность — в `ROADMAP.md` → «Кроссплатформенность».

## Известные проблемы и долги

- **Hot-plug проверен не до конца:** сценарий «выбранное устройство выдернули →
  откат на устройство по умолчанию» покрыт юнит-тестами плана
  (`devices::plan_device_update`) и кодом отката, но живьём не воспроизведён:
  Windows после нескольких `disable/enable` ответила «Device is pending system
  reboot» и отключить выбранную карту не дала. Проверить руками: выдернуть
  USB-карту при работающем приложении — должен быть тост
  «Устройство отключено: …», звук уходит на устройство по умолчанию.
- **Выдёргивание драйвера чтением конфигурации не лечится:** если выдернуть карту
  насовсем, `config.ini` сохранит откат (устройство по умолчанию), и после
  возврата карты выбор сам не вернётся — надо выбрать руками.
- **Групповая комната проверена не полностью:** приглашение/вход прокликать не
  удалось — окно DSH «поверх всех окон» перекрывает Albus, и клики агента
  попадают в него. Логика покрыта 22 юнит-тестами (calls.rs), протокол —
  round-trip тестами. Проверить руками: два-три узла, «Позвонить»/«Пригласить»,
  «Войти», затем в диагностике «N в комнате» и mesh у всех.
- **packet_loss_perc зафиксирован на 8 %:** при чистом канале это чуть
  снижает качество, при плохом — может быть мало. Нужен адаптивный: брать
  потери из link_stats() и подкручивать `encoder.packet_loss_perc`.
- **Счётчики приёма голоса живьём не спровоцированы:** на loopback-соединении
  потерь нет, поэтому в панели диагностики все нули — это правильные нули, но
  ветку «провал буфера / маскирование / перезапуск потока» надо увидеть на
  реальной сети или плохом Wi-Fi. Логика окна (дельта счётчиков) покрыта тестами.
- **В отчёте нет джиттера и потерь голоса в процентах:** сейчас есть счётчики
  событий приёма и потери QUIC (`lost_packets`) на путь, но не «потеряно N из M
  пакетов». Добавлять — когда появится NACK/адаптивный битрейт видео.
- **`gui/mod.rs` — монолит ~2 700 строк:** видео-логика маршрутов, оверлеи,
  настройки, диагностика и консоль в одном `impl RadioApp`; вынесение по файлам —
  первоочередной технический долг.
- **Тестов нет на GUI, network/iroh_service, video-win** — только чистые модули.
- Старый конфиг `config.ini` совместим, но ключи `mic_processing` / `input*_profile`
  остаются «мёртвыми» для новых установок.
- Проверить на живой машине после пачки 21.11: мьют (кнопка и `Ctrl+M`),
  тост при ошибке переключения динамиков, «Войти в комнату» из строки друга,
  имена участников, сообщение в чёрном окне видео вместо пустоты.

## Точка остановки (сессия 21.11, вечер, после проверки группы)

**Сделано и закоммичено** (`652e83c`, `73d16cd`, `2f4c694`, `78a88f3`):

- комната на N: приглашение в текущую комнату, `pending` с переотправкой и
  таймаутом, адресные отказы, `RoomMembers` (тег 17) для сборки mesh, вход по
  кнопке «Войти» (и Enter);
- голос: in-band FEC + PLC вместо повтора кадра, адаптивные `packet_loss_perc` и
  потолок битрейта по потерям/полосе QUIC, предбуфер на собеседника 60→150 мс;
- хост — наименьший id комнаты, пересчёт раз в секунду; уход из комнаты
  объявляется `CallEnd` всем, `IrohSync` после ухода не рассылается, mesh
  лечится `ensure_connected` раз в секунду, вошедший сразу регистрируется в
  списке (`register_peer`);
- `tools/agent/group.ps1` — N экземпляров с взаимной дружбой для проверок.

**Проверено живьём (три и два экземпляра):**

- три узла видят друг друга: «Эфир 3 узла», оба собеседника в списке, у всех
  одинаковый хост (`4017abeb…`), по две входящих P2P-связи у каждого;
- «Выйти из эфира» убирает ушедшего из списка **сразу** (было: до таймаута 12 с
  и «нет связи»), приглашение на него после этого уходит;
- приглашение → «Войти» → в комнате 2 узла, в логах `[КОМНАТА] Входим по
  приглашению …`, `Список комнаты …: 1 участник(ов)`, `… вошёл в комнату`;
- трансляция: издатель (не хост) отдаёт поток хосту (`Поток хосту … отдан`), хост
  ретранслирует (`принят в релей`, `Зритель подписался`), зритель принимает
  (`Подписка принята`) и показывает окно «Albus — трансляция» с картинкой и
  строкой «43 FPS · буфер 2.0 с · декод 3.6 мс»;
- диагностика на обоих узлах: «В комнате: 2 узла (вышли: нет)», RTT 0 мс,
  потерь 0, роль хост/гость определяется верно.

**Что осталось (не блокирует):**

1. Живой звук на реальной сети: рост FEC-счётчика при потерях и отсутствие
   «робота» — проверяется только ушами на двух машинах.
2. `packet_loss_perc` на чистом канале опускается до 0 % (FEC выключен) — это
   ожидаемо, но стоит убедиться, что при кратковременных потерях он поднимается
   обратно (сглаживание ±4 %, шаг пересчёта 1 с).
3. Релей проверен, но не на всех комбинациях (хост-издатель, позднее
   подключение); при желании — прогнать `group.ps1` со сценариями.
4. Мелочь UI: после входа по приглашению карточка звонка показывает «Узел 2 0:06
   Выйти» — можно причесать (сейчас это живой индикатор комнаты).

**Находка про инструмент:** клики мыши «перестали работать» из-за залипшей
боковой кнопки (`mouse_event(0x0084)` вместо `0x0100` XUP) — лечится
`mouse_event(0x0100, 0, 0, 1, 0)`; DSH висит поверх Albus, поэтому окно надо
поднимать `SetWindowPos(HWND_TOPMOST)` + Alt-трюк, со свежим handle (eframe
пересоздаёт окно после resize). Подробности в `AGENTS.md`.
