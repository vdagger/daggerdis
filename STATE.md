## Что это за проект

P2P голосовая рация и клиент для созвонов: чистый Rust, транспорт iroh/QUIC
(датаграммы для голоса, отдельное соединение для видео), GUI на eframe/egui.
Без серверов: комнату держит один из участников, при его выходе — миграция хоста.
Уже работает: голос (2 входа, эффекты, PTT), звонки, друзья, онлайн-статус, DM-чат,
трансляция экрана 1080p/1440p 30/60 fps звездой publisher → host → viewers.

- Объём: ~15 400 строк в `src/` (46 файлов), крупнейшие — `gui/mod.rs` (2 317),
  `network/video_link.rs` (2 043), `calls.rs` (898).
- Тесты: 95 юнит-тестов (config, calls, txbus, mixer, message, video_link,
  video_directory, presence, room, audio) — все зелёные на 2026-11-21.
- Платформы: Windows — основной таргет (видео только Windows);
  Linux/macOS собираются частично, готовность — в `ROADMAP.md` → «Кроссплатформенность».

## Известные проблемы и долги

- **105 коммитов не отправлены на GitHub** — единственная копия истории локальная.
- **Ошибки видео не видны пользователю:** `VideoSession::last_error` /
  `RemoteView::last_error` (gui/video_session.rs:313 и :361) никем не вызываются —
  при сбое декодера окно просто остаётся пустым.
- **Переключение динамиков может оставить без звука:**
  `restart_playback_stream` (gui/stream_control.rs:64) сначала ставит поток в `None`
  и только потом собирает новый; при ошибке воспроизведение не возвращается
  (у входа сделано наоборот — сначала собрать, потом заменить).
- **Нет реакции на hot-plug:** устройства перечисляются при старте и при ручной
  смене в настройках; выдернутый/подключённый микрофон сам не подхватывается.
- **`gui/mod.rs` — монолит 2 317 строк:** видео-логика маршрутов, оверлеи,
  настройки и консоль в одном `impl RadioApp`; вынесение по файлам — первоочередной
  технический долг.
- **Тестов нет на GUI, network/iroh_service, video-win** — только чистые модули.
- Старый конфиг `config.ini` совместим, но ключи `mic_processing` / `input*_profile`
  остаются «мёртвыми» для новых установок.

## Очередь на ближайшее (обновлять после каждой сессии)

Порядок — предложение; финально выбирает пользователь. Источник — аудит кода
от 21.11.2026 (см. `DEVLOG.md`), приоритет = польза / риск.

0. **Бэкап истории:** `git push origin main` (105+ коммитов) — снять риск потери.
1. **Быстрые победы** (1–3 часа, низкий риск), в порядке ценности:
   - **Мьют микрофона в UI + клавиша.** Логика уже есть (`AudioMixer::mic_muted`,
     mixer.rs:472) и вызывается из `txbus`, но переключатель доступен только через
     мёртвый `menu.rs` (`/mute`). Нужен тумблер в подвале консоли + глобальная клавиша.
   - **Вход в комнату из строки друга.** `join_room` в room_panel.rs:358 приватный;
     без этого попасть к другу можно только вставкой 64-символьного NodeID.
   - **Ошибки в UI, а не в консоль.** `last_error` декодера видео (video_session.rs:313,
     :361) мёртв; ошибки потоков печатаются только в stderr; отправка чата
     игнорирует результат (`let _ = send_bytes`, chat_panel.rs:53) — сообщение
     рисуется, но может не уйти.
   - **Безопасное переключение динамиков:** сначала собрать новый поток, потом
     заменять (stream_control.rs:64).
   - **Настоящие ники в «Участниках»** из `FriendsManager` по `node_id`
     (сейчас «Гость 3f2a»), затем — `nick` в `IrohSync` добавочным полем.
   - **Hot-plug аудиоустройств:** обновлять списки при открытых настройках,
     ошибку потока превращать в фолбэк на устройство по умолчанию.
2. **Диагностика сети и звука в UI + «Скопировать отчёт»:** RTT по presence,
   потери/джиттер голоса (счётчики уже есть в audio.rs:433), дропы видео, битрейт,
   «напрямую/через релей». Окупает все будущие разборы «почему плохо слышно».
3. **Приглашение в комнату и групповой созвон:** звонок сейчас строго 1:1
   (calls.rs), комната уже mesh на N; нужны `RoomInvite`/`RoomAccept` и вход по
   приглашению вместо NodeID.
4. **Текст в комнате:** `ChatMessage` доставляется только друзьям в личку;
   нужен широковещательный чат комнаты с историей в памяти.
5. **Видео:** NACK/ретрансмиссия из кольца `Recent` и адаптивный битрейт по
   потерям (`ROADMAP.md` §3 «Осталось»).
6. **Трей, системные уведомления, автозапуск** (`windows` 0.62 уже в зависимостях,
   новые крейты не нужны).
7. **Кроссплатформенность** по `ROADMAP.md` (Linux: firewall/keybind; macOS: .app).

## Не делать (противоречит архитектуре)

- Сервер, аккаунты, офлайн-доставка сообщений — ломает zero-server и E2EE.
- Автосохранение истории чата на диск — явное решение проекта (chat.rs:1-2).
- Свой UDP/STUN-фолбэк или вход по «IP:порт» — работа iroh и анти-имперсонация
  (`sender_id ↔ NodeID`) держатся на этом.
